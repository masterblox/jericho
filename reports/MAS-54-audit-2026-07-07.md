## Key Design Decisions

1. **PNG→PDF approach**: Pintura v8's processImage requires browser canvas/DOM globals and cannot run in Vercel Node cron runtime. Client-side `exportImage` produces a 1200x1800 PNG which `exportPrintPdf` embeds in a PDF. The PDF page box equals the image dimensions, so 300 DPI is achieved by ratio (1200px / 4").

2. **render_snapshot_url preserved**: The code intentionally does NOT overwrite render_snapshot_url with the prints URL. It keeps the source PNG path because the PDF path is deterministic (prints/<id>.pdf). This is a documented deviation from the ticket spec — per CLAUDE.md convention, code wins.

3. **Idempotency**: Re-runs download the same source PNG, render to the same deterministic PDF path (upsert: true), and the submit_print_job enqueue swallows unique violations.

4. **SEAM documented**: Printed sends require the wizard to upload a source render (currently blocked for printed in orders.place). Until that guard is relaxed, the handler throws MISSING_SOURCE_RENDER for printed obligations with null render_snapshot_url.
