## 4. token-diet — Cost Savings Analysis

Repo: github.com/Kulaxyz/token-diet (566 stars)
Tagline: "Always-on token-efficiency skill for coding agents. ~31% lower bill."

How it works (8 levers):
- Replies: lead with answer, no preamble/postamble
- Docs/memory/handoffs: minimum words, comment the why not the code
- Tests: key + critical/edge paths only, 10 max per session
- Code: YAGNI, concise but idiomatic
- Context: grep before read, batch reads, fewer turns
- Tools: batch independent calls, stop when enough to act
- Sub-agents: delegate bounded search to cheaper models
- Guardrails: concision never compromises correctness

Levels: on (default), lite (communication only), ultra (telegraphic), off

Works with: Claude Code, Codex, Cursor, Windsurf, Cline
Does NOT have a Hermes-native implementation yet.

Relevance to fleet: HIGH. The principles directly apply to all fleet agents.
Jericho already follows many of these (lead with answer, batch calls, grep first).
But our agents vary — DEV is verbose, Donald drafts long emails, Iris over-explains.

Fleet adaptation:
- Could create a `token-diet` fleet skill that applies these principles
- Would NOT be an installable tool (token-diet is Claude Code/Codex specific)
- Would be a SYSTEM PROMPT INJECTION into agent configs
- Estimated savings: 20-35% token costs across fleet
- Implementation: add token-diet principles to each agent's system prompt

Recommendation: IMPLEMENT as fleet skill. Create jericho-ops/skills/token-diet-fleet/
with per-agent prompt fragments. Estimate: 1-2 hours of work. Worth ~$50-150/month
in token savings depending on fleet volume.
